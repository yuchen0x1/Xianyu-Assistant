# Webhook 投递与排障

适用于 v3.5.24（2026-11-13）；实现基于 3.5.23 的兼容改进。

## 使用

在「Webhook 配置」创建端点，填写名称和公开 HTTP/HTTPS 地址。可选签名密钥；编辑时留空保留原密钥。不选择监听事件表示全部事件，选择后只发送对应事件。

“最多尝试次数”包含首次发送，范围 1–10。为了兼容旧配置，后端仍接受旧 `retryCount=0` 并按尝试一次处理。网络超时范围 1–60 秒。失败先持久化，再按退避时间由每分钟一次的扫描重投；下次重试时间是最早可执行时间，不保证到秒触发。禁用端点会暂停后台扫描投递。

点击每张端点卡片的「投递历史」，查看最近 100 条持久化记录，按等待、成功、失败或结果未知筛选；点击「刷新历史」获取新状态。此筛选仅作用于已加载的最近 100 条，并非全历史检索。

记录包含投递编号、事件、累计尝试次数、HTTP 状态、失败原因、下一次重试和送达时间。仅展示载荷字段名，不展示值或签名密钥。错误会保留刷新入口，网络恢复后可继续读取。测试按钮直接发送测试请求，不生成业务投递历史。

失败记录无下次重试时间时，自动重试已停止：可能达到次数上限或载荷已损坏。先检查接收端、配置及错误信息。本次没有新增手动补发，以免不明确的业务副作用被重复执行。

## API 与兼容

`GET /api/webhooks/{id}/deliveries?limit=100`，要求登录及 `webhook:read` 权限；原接口继续保留，limit 最大 200。返回脱敏 DTO，无原始 payload。

业务 POST 保留现有 JSON 结构 `{ event, timestamp, data }` 及原 HMAC-SHA256 签名算法，增加/修正请求头：

| 请求头 | 含义 |
| --- | --- |
| `X-Webhook-Event` | 事件类型 |
| `X-Webhook-Id` | 当前数据库内稳定的投递编号，自动重试保持不变 |
| `X-Webhook-Attempt` | 本次尝试序号，从 1 开始递增 |
| `X-Webhook-Signature` | 配置密钥时附带的 `sha256=` + Base64 HMAC |

接收方应先用现有算法验证原始请求体，再按“发送实例 + X-Webhook-Id”去重。编号在不同数据库间不保证唯一。时间戳随重试更新，不能用整个请求体或时间戳作为稳定去重键。测试请求不带业务投递编号。

成功会清除旧失败原因及下次重试时间，同时保留累计尝试次数。历史版本已经清零的次数不能凭空恢复。无需数据库迁移；改动只修正实体更新策略和业务逻辑。现有坏状态不会批量改写，后续执行时按当前上限复核。

## 边界

- 进程内占用保护覆盖首次排队与后台重投；适用于当前单机 SQLite 部署。多个进程共享数据库需要持久化租约，不能据此宣称支持集群。
- 外部接收成功、落库前进程崩溃仍可能重复投递。接收方必须做幂等处理，不保证端到端恰好一次。
- 公网地址检查、DNS 固定和禁用重定向继续保留。当前修改未改变网络访问策略。
- HTTP 客户端异常不会直接输出包含完整 URL 的消息；保留异常类型供排障。实际公网接收端与真实闲鱼账号链路需另外验收。

## 复验

先在 `vue-code` 执行 `npm run build`，根目录执行 `./mvnw.cmd -B -ntp package`。再执行：

```powershell
./mvnw.cmd -B -ntp '-Dtest=WebhookServiceTest,WebhookDeliveryReliabilityTest' test
./mvnw.cmd -B -ntp '-Dtest=WebhookBrowserIT' test
```

`WebhookBrowserIT` 为显式运行的 Windows 浏览器集成测试，默认 `mvn test` 不自动运行。使用现有 Playwright/Chromium，启动刚构建的 JAR，随机本机端口，数据与日志全部位于 `target/webhook-browser-*`。自动更新和自动备份关闭；不会导入现有数据或登录真实闲鱼账号。测试创建初始管理员和禁用端点，并向隔离库注入明确标注的历史测试记录，以验证 API、筛选、刷新和脱敏展示；HTTP 投递重试另由 SQLite 集成测试及受控 HTTP 替身验证。结束时停止自己启动的进程。
